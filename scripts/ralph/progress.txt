## Codebase Patterns

### Supabase & Database
- Use `as unknown as Json` for type casting complex objects to JSONB fields
- Use `as never` for Supabase insert/update calls to bypass type inference issues
- Cast returned data with `as Type` (e.g., `as IntelligenceReport`)
- Use `!= null` instead of `!== null` to catch both null and undefined in TypeScript
- Use `.single<{ col: type }>()` generic override when Supabase browser client infers `never` for typed queries
- RLS policies need separate policies for each operation (SELECT, INSERT, UPDATE, DELETE)
- RLS for child tables: `EXISTS (SELECT 1 FROM parent WHERE parent.id = child.parent_id AND parent.user_id = auth.uid())`
- Storage RLS uses `auth.uid()::text = (storage.foldername(name))[1]` for ownership check
- Storage path pattern: `{user_id}/{bucket-purpose}/{brand_id}/{timestamp}.{ext}`
- Period dates for usage: periodStart = first of month, periodEnd = last of month
- Query usage by period_start with ISO date string (YYYY-MM-DD format)

### API Routes
- Quota check pattern: return 429 with { error, remaining, limit } when exceeded
- Check for existing resources before creating (409 Conflict pattern)
- For routes that don't use the request object, use `export async function POST()` without parameter
- Fetch intelligence reports via GET /api/generate/intelligence?brand_id={id}
- BrightData API returns BrightDataResponse<T> which can be success or error

### UI Components
- Parse JSONB fields from database using a helper function (parseXxx) for type safety
- Use expandedSections state object for managing multiple collapsible sections
- Modal state pattern: isOpen prop + onClose + onGenerated callbacks for parent control
- Auto-selection pattern: if (data.length === 1) setState(data[0].id) for single-item lists
- Filter by product uses server-side filtering, filter by status uses client-side filtering
- Download pattern: fetch blob, createObjectURL, create anchor, click, cleanup
- Export functionality: Blob + URL.createObjectURL + anchor.click pattern
- Progress bar color logic: <80% green (#10b981), 80-99% yellow (#f59e0b), 100% red (#dc2626)
- Use backdrop-filter: blur() for modal overlays

### Generation & AI
- Use `generateImageWithRetry` / `generateVideoWithRetry` for automatic retry on rate limits
- Image generation prompts work best with specific persona details, not generic descriptions
- UGC-style prompts should mention "slight imperfection" for authenticity
- Video generation takes longer (30-60 seconds) - include timing note in UI
- Mark personas as "needs_revision" instead of rejecting when values aren't specific enough

### Stripe & Subscriptions
- Stripe Billing Portal provides built-in UI for payment method and invoice management
- Cancel at period end pattern: user keeps access until billing cycle ends
- tierPricing and tierLimits from lib/stripe/client provide all subscription configuration
- Unlimited values represented as -1 in tierLimits
- Intelligence reports don't have a limit column in subscriptions - use tier-based lookup

### Shared Components
- Shared components live in `components/shared/` imported via `@/components/shared`
- EmptyState accepts `icon` as either a predefined type string or custom ReactNode
- LoadingState presets: cards, products, personas, creatives, list, table
- Use barrel exports (index.ts) for cleaner imports

### Next.js 15
- Use `use(params)` with Promise<{...}> for Next.js 15 app router params

### Admin Dashboard
- Admin uses service role key (SUPABASE_SERVICE_ROLE_KEY) to bypass RLS
- Admin role stored in user_profiles.role column
- Admin layout at app/(admin)/ with force-dynamic and AdminShell
- Amber/gold accent color distinguishes admin from user dashboard — swap `--color-plasma-violet` to `--color-plasma-amber` and rgba(139,92,246) to rgba(245,158,11)
- All admin actions must create audit_logs entries
- Moderation columns (moderation_status, moderation_notes) on brands, personas, creatives
- audit_logs is append-only (no updated_at); system_settings uses TEXT PK (setting key name)
- Use `admin.auth.admin.getUserById(uid)` to get user email from auth.users (service role only)
- For cross-table user email lookups: collect IDs → batch Promise.all getUserById → build emailMap
- For service-role-only tables: enable RLS with no policies (blocks all user access)
- Admin route group `(admin)` contains `admin/` URL prefix — `/admin` maps to `app/(admin)/admin/page.tsx`
- Admin nav links: Dashboard, Users, Content, Subscriptions, Analytics, System, Audit Log
- AdminShell receives adminUser as serializable prop from server layout (no client-side auth fetch needed)
- URL search params pattern for admin pages: server component reads `searchParams` Promise, client component uses `useSearchParams()` + `useRouter().push()` for interactive filters
- Debounced search input: `useEffect` + `setTimeout` ref with 400ms delay, clear on cleanup
- Badge color conventions: emerald=active/success, rose=disabled/error, amber=admin/warning, violet=professional, cyan=starter/info
- Admin detail pages use InfoRow pattern (icon + label + value) with `divide-y divide-white/[0.04]` separators
- Use `maybeSingle()` for queries that may return 0 rows (subscriptions, usage_tracking) to avoid PGRST116 errors
- Breadcrumb pattern: `Admin > Section > [entity]` using ChevronRight separators and Link components
- Server actions pattern: `"use server"` file in route directory → client component imports and calls via `useTransition` + `startTransition`
- `revalidatePath()` in server action + `router.refresh()` in client to refresh RSC data after mutations
- ConfirmDialog pattern: fixed overlay with backdrop-blur, AlertTriangle icon, optional children for extra inputs (e.g., email confirmation)
- Content moderation actions are generic: `updateModerationStatus(contentType, contentId, newStatus, reason)` works for brands, personas, creatives
- Moderation notes use append pattern: `[ISO_timestamp] status: reason` per line — never overwrite, always append
- Content page tab nav: `tab` search param, reset other params on tab change, each tab is a separate client component
- Recharts pattern: server page fetches data → passes to "use client" chart component. Use ResponsiveContainer in a fixed-height parent. Dark theme: tick fill rgba(255,255,255,0.4), grid stroke rgba(255,255,255,0.06), custom Tooltip with glassmorphism
- Data point thinning: for charts with many days (90d/1y), thin to ~45-52 points with `thinDataPoints()` helper, always include last point
- Recharts PieChart/donut: use `<Pie innerRadius={60} outerRadius={100}>` for donut shape; custom label via `label={renderPieLabel}` function; Cell component for per-slice colors
- Subscription distribution is date-range-independent (always shows current active/trialing subs); usage overview respects date range
- Cohort retention: group subs by `toYearMonth(created_at)`, check active at month N via `updated_at > monthEndDate`. Cap at 12 months × 12 columns.
- Churn analysis: only count paid tiers; "active at start of month" = created before month start AND (currently active OR became inactive during this month)
- For admin API routes (polling endpoints), use `isAdmin()` instead of `requireAdmin()` — requireAdmin uses redirect() which is meant for pages
- Realtime monitoring lives at `/admin/analytics/realtime` with API route at `/api/admin/realtime` for client polling
- Detailed analytics lives at `/admin/analytics/detailed` as a separate page linked from the overview page
- Usage overview counts from `personas.created_at` and `creatives.created_at` (with `creative_type` distinguishing image/video)
- For counting distinct users of child tables (personas, creatives, audiences, reports): use `brands!inner(user_id)` join + `Set<string>` to deduplicate user IDs
- System settings stored as individual rows with TEXT PK (key name) and JSONB value; tier limits stored as `tier_limits_{tierName}` keys with JSONB objects
- Filter out moderated content: `.not("moderation_status", "in", '("disabled","deleted")')` — PostgREST uses parenthesized string, not array
- Disabled account check: query `user_profiles.disabled_at` after auth succeeds; if not null, sign out and show error
- Impersonation uses HTTP-only cookies (`adforge-impersonate-id`, `adforge-impersonate-email`) set/cleared via server actions
- API route for impersonation status check: GET `/api/admin/impersonation` returns `{ isImpersonating, userId, email }`; POST clears impersonation
- ImpersonationProvider context wraps DashboardShell children — use `useImpersonation()` hook in any client component to check status
- Read-only impersonation: event delegation on `<main>` element blocks button clicks and form submissions while allowing link navigation
- Audit logs for impersonation: `impersonation_start` and `impersonation_end` actions with `target_email` in details
